# P2 交付使用指南

## 1. 范围与交付状态

P2 当前主线已到 **B3 / C / D 基础闭环，默认新工程为 schema4**：素材与自然剧本预检生成、真实分页、基础编辑与已有演出参数调整、受限视频插播、便携保存和 MP4 导出。本轮只做整体验收收口，不扩功能，不代表完整自动创作工具或所有旧 schema 操作均已兼容 v4。

已有阶段证据与最终交付状态必须分开。当前已补含视频回接、外部受控导入实现，六分钟连续播放与10800帧完整MP4、455帧三方画面对照已有独立证据；原生拖放类型/限额/同名/便携/导出在途矩阵、真实素材12轮会话恢复及混音路径核验已补齐；历史间歇超时仍保留未定位风险，干净系统与人工作品验收尚未通过。**不能据此宣布全P2完成。** 最新逐项状态以 `docs/P2-最终交付清单与验收门槛.md` 为准；本文末节旧待办描述尚需跟随最终证据更新。

## 2. 部署与启动

### 交付目录

以下仅为相对目录示意，不包含用户真实路径：

```text
交付目录/
├─ P2/
│  ├─ 启动P2编辑器.bat
│  ├─ run-electron.cjs
│  ├─ assets/
│  ├─ examples/
│  └─ …其余完整程序文件
└─ p0/
   ├─ node_modules/electron/dist/  ← Electron 44.4.5 完整目录
   └─ tools/
      ├─ ffmpeg.exe
      └─ ffprobe.exe
```

**P2 不是独立安装包。** 必须保持相邻 p0 依赖布局；Electron 不能只复制 exe，其 DLL、资源、locales 等必须完整。`npm install` 不会安装上述相邻 Electron 运行时或媒体工具，不可代替补齐交付目录。

应用应放在当前账户可写的位置，允许写入 P2 用户数据和 `runtime-output/`。不承诺 Program Files 等受保护目录直接可用，不将管理员运行当成默认方案。更新后先自行保存工作，再重启 P2 加载；不要强关别人的窗口。

### 两个启动入口

- **BAT**：双击 `P2/启动P2编辑器.bat`。入口直接使用提供的 Electron，不需另装 Node；已在完整依赖隔离副本、仅系统目录PATH环境实际运行原BAT并验证GUI就绪。验收副本追加了观察器，不能等同未经插桩的人工双击或干净Windows验证；部署步骤见 `docs/P2-干净Windows部署验收步骤.md`。
- **Node**：已有 Node 时，在 P2 目录执行：

  ```powershell
  node run-electron.cjs
  # 只读依赖路径存在性自检，不启动子进程、不写文件
  node run-electron.cjs --check
  ```

**`--check` 已实现，本轮实际运行返回 `ok: true`，errors/warnings 为空。** 它仅做依赖路径存在性自检，不完整扫描 Electron DLL/resources；返回成功不是运行时完整性、GUI 启动、媒体处理或所有功能就绪证明。

缺 ffmpeg/ffprobe 按 warning 处理，普通编辑不因此禁用；实际 MP4 导出、视频探测/归一化/播放处理不可用。缺工具负向场景仍待最终验收。缺 Electron 或其文件不完整无法保证正常启动，不应忽略错误继续交付。

## 3. 五步完成作品

### 第一步：素材 + TXT/MD 预检生成

1. 准备 UTF-8 自然剧本 `.txt` / `.md`、分类素材根目录（背景、角色、配音、音乐、音效等，视频放“视频”类别）与素材配置 JSON。角色/配音/图片映射仍需配置，不承诺完整可视化配置编辑器。
2. 右侧“剧本预检”选择剧本、素材目录和配置，点击预检。按诊断行号修正；对白可绑定素材、设为无配音或恢复自动匹配。
3. 需要调整阅读时长或分页容量时使用顶部“阅读与分页”。保存设置后旧报告失效，必须重新预检；不会重排已打开工程的页时间。
4. 点击“计算生成概要”：实际测量分页并校验媒体，核对预计总时长、对白/页数、有声与无声对白、角色及素材信息。语法预检通过本身不代表媒体有效；概要不会发布工程。含压缩音频或视频时会先规范化媒体，正式生成还会再次处理，暂未缓存复用。
5. 点击“确认概要并生成基础工程（另存）”，输出位置与素材根目录互不包含。输入或分页变化会要求重新计算概要；生成仍执行最终校验。生成新目录，不覆盖旧工程；成功后用“打开工程”显式打开结果。

**压缩音频新增入口：**剧本素材目录的“配音/音乐/音效”可识别`.ogg`（Vorbis/Opus）与`.mp3`，概要及生成时转为托管48kHz PCM16 WAV，原件不改。每个输入/输出最多256MiB、最长600秒、单/双声道；多流/链式OGG、循环标记不支持。该支持不等于旧手动配音导入框也接受这些格式。

含转换音频的工程来源和回接记录使用v2。回接时必须一起选择文本、素材目录、配置及`.replay-map.json`：包内是真正的WAV，通过映射保留原OGG/MP3逻辑文件名；不要自行改扩展名或丢弃映射。旧版程序不能读取新来源记录；完整工程与原件继续保留备份。当前整链验证状态见《P2-压缩音频接入与修补记录.md》。

**两个文本入口不能混用：**

| 入口 | 用途与边界 |
| --- | --- |
| 剧本预检 → 生成基础工程 | 解释自然剧本、素材匹配与支持的演出命令，生成新工程；不会静默替换当前工程与草稿 |
| 文本导入 / 文本转对白 | 直接输入或 UTF-8 TXT，向当前工程创建当前语言对白；旧 S3 入口 TXT 上限 256KiB，拖入只设预览位置，需显式创建。不是整份自然剧本生成，不解释完整演出命令，不自动扩展场景或复制配音；仍以当前 schema 校验为准 |

### 第二步：编辑并应用

- 修改对白、页文本、角色或声音后，按面板要求“应用”才进入工程。保存、导出或切换对象遇草稿提示，先明确应用或放弃，不假设自动合并。
- B3 有配音对白保持整句声音连续，不按页重播或拉伸配音；无配音自动时长只是阅读估算，不是逐词语音对齐或主观舒适度保证。
- C“场景演出参数”**只编辑已有对象**：角色透明度、黑罩、对白显隐/清字幕、标题时间与基础样式、BGM 尾部淡出。不提供任意演出事件新建/删除/复制或复杂拖拽轨。
- 默认模板没有 C 演出对象，显示“暂无已有对象”正常；可通过支持的自然剧本命令生成相应演出，不应将空态判为 v4 禁用。
- schema4 现支持普通角色实例、整段对白、独立音轨、背景事件、表情事件、配音片段的复制/粘贴/删除。复制角色共享模板，并保留关联透明度演出；删除实例不删除模板、不将对白说话人转为旁白。选择单页时不冒充整段操作，背景事件复制不包含全局转场。
- 单页独立剪贴板、视频/全局演出复合复制、跨工程/跨格式仍未开放。生成来源基线不被手工复制/删除改写，完整工程可保存，但TXT/回接可能有损或拒绝；不要手改schema号绕过校验。

### 第三步：预览检查

播放并随机/逆向定位，检查分页、姓名、末页保持、角色、标题/黑罩、声音和视频边界。标题过长可能被布局检查拒绝，应缩短文字或调整支持的样式，不承诺自动缩字/长标题分页。

D 视频通过 `@视频 文件.mp4` 生成：单次、阻塞、全画面 contain 黑边、30fps。视频覆盖最高层，底层状态继续按绝对时间求值；开始硬截此前声音，结束仅将当时仍活动的 BGM 从头重播。voice/SFX 不恢复，已停止或自然结束的 BGM 不复活。

**不支持** trim（裁剪）、loop（循环）、speed（倍速）、同时/重叠插播及独立视频剪辑面板。视频回接包现已支持受控source3/map3：规范化MP4与派生WAV成对保留，原件离线可重新生成，不对已验证托管视频重复有损编码；不支持任意拓扑改动的无损文本往返。单输入最多 **256MiB / 60秒 / 1800帧**；规范化输出总预算 **512MiB**，全部使用视频的解码帧缓存总预算 **256MiB**。超限拒绝；预算内也可能因解码缓存不足失败，不保证任意高分辨率/高噪声素材可用。

### 第四步：另存便携工程并重开

- 另存到新目录，由保存链复制托管素材到 assets。分发完整工程与资源目录，不只发送 JSON；再打开另存结果检查。
- 默认模板 `P2/examples/rain-corridor-v4.json` 由程序以 **P2 根 assets** 加载，不是 examples 下自带资源的 portable 工程。不要通过“打开工程”直接打开 raw 模板来试验便携性；应正常启动默认工程后另存。
- 旧工程只走明确支持的显式升级流程并另存，不覆盖旧格式原件，不让 P1 写回未知新字段。
- 完整工程是权威保存格式。纯 TXT 无法无损表达全部手工帧、样式和演出；受控回接也有拓扑/自定义部件限制；视频回接包仅接收完整来源映射与经哈希、媒体解码验证的托管视频/派生声音，缺失或篡改拒绝，不用纯TXT猜回视频资源。保留原剧本、配置和生成来源文件备份，不用回导 TXT 替代正式工程保存。

### 第五步：导出 MP4

确认草稿已处理、媒体工具齐全、输出可写且空间足够，再执行导出。视频准备、字体布局、模型校验出错时先解决原因，失败输出不可当作成片。

保留历史输出名 `p1-preview.mp4`，不重命名；名称不代表读写 P1 用户数据。核对实际 MP4、时长、首尾画面与声音。预览成功不自动等于导出成功，MP4 也不替代可编辑工程备份。

## 4. 恢复与数据安全

- 两入口规则一致：**保留显式 `REPLAY_RECOVERY_DIR`**（相对值按 P2 目录解析）；未设置时默认 `P2/runtime-output/recovery`。已完成实现/静态对齐，并通过隔离两进程的实际恢复验收；BAT 正向启动未运行，不能把静态检查当 GUI 启动验收。
- 不将恢复目录指向 P1，不让多实例覆盖同一工程。显式目录应记录并确认可写。
- 已有恢复/显式打开工程优先于新默认模板，保持原 schema，不自动升级。启动后仍见旧工程不等于启动失败。
- 自动恢复只覆盖**已应用的 project/code 草稿状态**，不保证恢复所有未应用表单输入，也不是正式保存。
- 恢复后检查内容、资源与版本，另存新副本。排错先备份工程、assets、恢复数据、用户设置和日志；**不要删除用户数据或恢复目录来“重置”问题**。

### 外部文件拖入（S4）

从Windows Explorer拖入后，在“外部文件”页明确每项用途和目标，先“校验并预览”，核对影响后再“确认导入”。共享模板或整段配音替换需要额外确认，不靠文件名自动覆盖。可以取消重新选择；一批最多20项，一项失败整批不提交，一次导入对应一次撤销。

- PNG/JPEG：背景、图片部件、新角色或明确的共享底图/表情槽。
- WAV/OGG/MP3：音乐、音效或明确已有对白的整段配音替换；压缩声音规范化为托管WAV。
- TXT/MD：最多256KiB UTF-8字面文本创建对白，不执行剧本或HTML；长文本预览会明确截断。
- MP4不走该入口，仍通过剧本`@视频`接入。取消或源文件变化需重新拖入；不要绕过授权提交任意本机路径。
- 导入后另存便携工程会复制托管资源，不再依赖外部原件；撤销不立即删除已托管文件，以保证重做安全。
